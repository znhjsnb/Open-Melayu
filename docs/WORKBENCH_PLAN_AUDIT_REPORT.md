### 3.2 已隔离复现的旧服务器问题

依据旧 `app/server.py` 第 17、191–225 行，提取方法后使用本工程假数据：

| 复现 | 观察 | 迁移要求 |
| --- | --- | --- |

## 4. 数据管线：C01/C03/C07

### 4.1 双轨必须允许第三种真实状态

`is_enriched` 是精编标志，不能同时承担数据可用性和权威认证。保留它，并增加如 `data_state = enriched | source_only | missing_source`：

- enriched：七维结构及本批门禁通过；不等于 DBP 逐字认证。
- source_only：有与本词确切对应的词典原义，来源类型、词典名、URL/缓存标识可追踪；Jawi/音节各自允许缺失。
- missing_source：仅能保证候选词头、已有可靠元数据；明确资料待补，不能伪造 DBP 原义或 Jawi。

必须以“有效精编 + 原义可用且未精编 + 资料缺失 = 15,000”守恒；状态互斥，索引 ID 与详情一一对应。远端若确有全量语料，应经受控导入和同一验证器核验后更新计数，不凭集群进度口述宣布完成。本地非空词典字段也可能是根词关联结果、同形异义词或解析串项；审核失败进入缺口清单。

精编层与 DBP 原义层分别保留，按字段选择展示，不整对象覆盖。`dan` 等词缺独立 Kamus Dewan 逐字原文，`ada` 等 Jawi 有交叉核验边界；见既有批次说明。不能在导出时抹掉这些标注，或将精编改述反标为 DBP 原文。

导入精编时选定单一主来源（可使用逐词文件，批次数组用于交叉校验），对同 ID 内容冲突硬失败；不采用“最后扫描到的文件胜出”。输入异常必须出清单，不能 silent skip 后假报 15k 完成。

### 4.2 Windows 保留名只在最终输出层解决了一半

`a`–`z` 加 `other` 是 **27 个逻辑分片**，方案的“26 个”须改正。聚合输出避免 `con.json` 是正确方向，但 `prpm_client.py`、连续爬虫仍按词头生成路径，采集器则使用 `_con.json` 映射；精编逐词生产也存在同一问题。导出器不得直接打开 `raw/prpm_cache/{word}.json` 假设它一定可用。统一安全文件名解析与显式映射；新输入推荐稳定 ID/哈希文件名并保留词头字段。大小写、Unicode 规范化冲突、尾点/空格和跨平台导入也必须检测。**不能宣称 Web 聚合分片彻底修复了上游 B05。**

稳定 ID 不使用会随词频调整变化的 rank。当前可以用规范化词头作为 lexeme key，另存 rank；将来同拼写多个词位需显式词位 ID。建立词族时区分实际派生、重叠、词形缩略、历史来源和相关表达；不能把所有 word_family 都标为可逆派生，也不能把词根作为唯一入口。

### 4.3 原子发布与缓存版本协议

建议最小布局：

```text
app/static/data/manifest.json                 # 小型当前指针，必须重新验证
app/static/data/builds/<build_id>/index.json   # 不可变
app/static/data/builds/<build_id>/shards/a.json
.../b.json .../z.json .../other.json
```

这保留 27 个按字母分片，仅给固定 URL 增加发布版本隔离。manifest 至少包含 `schema_version, build_id, index URL/hash/bytes, shard URL/hash/bytes/count, total/enriched/source_only/missing counts`。构建 ID 反映输入内容与 schema/导出器版本；同日多个批次不能只用日期区分。

1. 单导出写入者，读取已提交的输入快照；采集/精编写临时文件后原子替换，或用就绪清单，避免读到半个 JSON。不可把正在变动的目录扫描当作一致快照。
2. 在新版本目录生成所有资产，校验计数、类型、键、引用、哈希、UTF-8 和跨层一致性。序列化/校验失败不得触碰当前发布指针。
3. 所有文件关闭后，以同目录临时 manifest + `os.replace` 发布指针；Windows 文件占用导致替换失败时保留旧版并报告，不能先删旧文件。逐文件 replace 不代表多文件原子发布。
4. 页面在线启动/刷新读取新的 manifest；Worker 固定使用一个 build_id。Cache API 的索引键、IDB 的分片键、内存和 inflight 键都带版本。详情请求携带页面版本，不读取另一个版本的同名字母文件。
5. 当前 manifest 返回 no-cache 或使用明确 bypass/revalidation 策略；不可变版本资源可长期缓存。Cache API 不自动遵循 HTTP 缓存头，必须由应用控制版本与淘汰。[MDN Cache](https://developer.mozilla.org/en-US/docs/Web/API/Cache)
6. 新版索引完整验证成功才切换；失败保留旧完整快照并显示可重试状态。不混用“新索引 + 旧分片”。离线只使用上次已验证的 manifest 和相应缓存。
7. 保留旧版供打开的标签页读取；不能刚发布就删掉旧目录/全部缓存。清理至少考虑活动客户端版本及磁盘预算；无法满足旧版请求时提示整体升级，不能回退到另一版本的同 ID 数据。仅“保留最近两版”并不能保证所有长期开页可用。

旧 `data.js` 有人工 DATA_VERSION，旧 Worker 对固定索引 URL 执行 cache-first；旧 db.js 的 IDB 键带版本，但 fetch URL 不带版本。单纯重跑导出器而未变更版本，刷新可能永远命中旧索引；即使改了版本，旧页仍可能抓到被覆盖的新分片。因此“每 1,000 词导出一次，刷新立即热更”只能在上述协议下成立。它是刷新更新，不是无需刷新实时推送。

## 5. 性能与持久化边界：C08/C12

### 5.1 15k Worker 内存

15,000 个轻量索引记录对现代桌面浏览器原则上可承受。这里的“客户端 0 算力”应改为“检索不依赖后端计算”：浏览器仍消耗 CPU、堆内存和电量。

假设最终 UTF-8 索引确为约 3.5 MB，每词预算只有约 233 字节。解析后的字符串、对象/数组、规范化副本、词族/别名倒排表和排序结果均有开销，不能把文件大小当常驻内存。**规划估算**：单 Worker 索引与辅助结构约 15–40 MiB，首次下载、JSON 解码、response.clone、规范化和 GC 瞬间可规划 30–80 MiB；这是容量预算范围，并非测量值或浏览器引擎保证。若索引包含全部中文长义项，文件会变大，估算也需重做。多标签页通常各有自己的 Dedicated Worker，不能按单页预算乘零。

不要把 15k 全量对象 postMessage 给主线程；只传当页结果、ID 与所需摘要。避免保留多套完整索引副本。为词根和别名预建 map，普通精确/前缀优先，OSA 仅对候选长度接近的词启用；对很短查询、中文和 Jawi 不默认全量模糊。旧 Worker 已有有界 OSA 和长度阈值，应保留其边界思路，扩展长词时同步调整缓冲区大小。

<5ms 只能作为指定机器、指定查询类别的 Worker 内部目标，不能承诺所有前缀/中文/别名/模糊和排序均低于 5ms。一次全量排序本身可能超过预算；Worker 也只有自己的事件循环，旧请求虽可丢弃响应，仍可能阻塞新请求的执行。必要时合并待处理查询并分段让出事件循环，保持“最新输入优先”。

### 5.2 27 个分片并不均匀

真实候选分布：m=2,231、p=1,586、b=1,447、s=1,396、k=1,193；other=4、x=11、q=17。m 占 14.87%，不是每片约 15,000/27 的平均规模。

当前 20 词紧凑 JSON 单词体积最小 3,700、均值 4,988.3、最大 7,117 字节。仅按这个均值外推，完整 15k 约 74.8 MB（71.4 MiB），m 单片约 11.1 MB（10.6 MiB），不含字典键和包装开销。**高频小样本不代表后续分布，以上是风险量级估算，不是全量产物实测。** source_only 初期可能更小，逐批精编后会增长。

字母分片在 localhost 的请求数量并不成问题；真正风险是第一次点 m 需读取/解析整片，以及 IndexedDB structured clone、事务写入、再次读回大对象对主线程的影响。Worker 检索不会自动把 db.js 的解析/克隆也移入 Worker。

建议先保留 27 片，构建输出各片 bytes/词数/最大记录，客户端限制内存 LRU（按字节预算优于固定三片）并复用已解析对象。最大分片如导致 >50ms 主线程长任务或超出详情时延门禁，再把解析/持久化移到 Worker，或按 manifest 划分子片；子片是明确的后续方案修订，不能悄悄改变既定路由。不要提前为 15k 引入复杂数据库服务。

### 5.3 IndexedDB 条件

- 内存、IDB、网络三级回退；同一版本/分片的并发请求共享 Promise，失败后清除 inflight，允许重试。不同词快速点击不重复下载整片。
- 网络下载/哈希/解析完成后才开启 readwrite transaction；不在事务内等待 fetch。以 transaction.oncomplete 确认保存成功，单个 put.onsuccess 不代表事务已提交。[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)
- 下载成功即允许显示详情，持久化可异步完成；失败应提示本次未保存，不能为“缓存写入”长时间阻塞阅读。
- `QuotaExceededError`、存储禁用、私密模式、损坏数据、transaction abort、open error/blocked、versionchange 均有可恢复路径；open 设置有限等待，不让页面无限挂起。迁移时旧连接响应 versionchange 关闭，不为每个数据批次提升 DB schema version。
- 缓存验证类型/版本/必要字段；损坏时清理该条再联网重取。缓存清理只删本项目命名空间，不调用全 origin 清空。
- Cache API 与 IDB 共享该 origin 的存储预算；可读 estimate，完整下载前按 manifest 预估空间，必要时申请 persist 但不假定获准。浏览器仍可驱逐非持久数据，清理站点数据或私密会话结束也会丢失缓存。[MDN 配额与驱逐](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

“同字母再次查词 0 网络请求”成立条件是同一版本缓存有效且未被清理；不能理解成永久可用。端口不同的 8765 与 8766 属于不同 origin，浏览器存储隔离；仍建议用 `open-melayu-*` 名称防止未来搬站误清理。固定使用 `127.0.0.1:8766`，不要启动器随机改成 localhost 或备用端口，否则缓存身份也会改变。

## 6. 离线与平台：C04–C06

### 6.1 Dedicated Worker + Cache API 不等于可离线重开

Dedicated Worker 负责搜索，不是 Service Worker。IDB 保存了词条，也不能替浏览器在停服后提供 index.html、CSS 和模块。方案应继承旧 `sw.js`，缓存完整页面壳、worker/data/db 模块、图标和选定字体；检测 `window.isSecureContext` 与 API 可用性。loopback 在现代浏览器通常可作为可信本地来源，仍须在目标 `http://127.0.0.1:8766` 实测注册和控制成功。[MDN Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)

离线能力需分清：外网断开但本地服务仍运行；停本地服务后在已安装 SW 的页面刷新/重开；只有已下载分片可读；全量 27 片及索引/页面壳已验证保存后全库可读。按需下载本身只支持部分离线。若产品沿用旧版“完整离线准备”入口，则继承顺序下载、暂停/恢复、计数与错误反馈；不能显示 27/27 就忽略持久化失败。第一次尚未安装 SW 的用户无法在停服后凭空打开页面。

SW 新版激活不能粗暴 skipWaiting + claim 后让旧页任意混用新模块与旧 schema。对页面壳采用一致的发布版本；若保持网络优先，需证明其模块图不会在更新中跨版。更新失败保留已验证旧壳；缺失 JS/JSON 不允许回首页假装成功。语音包与未缓存内容不包含在“已缓存可离线”承诺内。

### 6.2 Windows 静默启动

Python 官方明确说明 pythonw 下 stdout/stderr 可能为 None，旧代码本次隔离复现也在该条件下立即报错。应在使用前判断流及 reconfigure 能力，使用 UTF-8 文件日志并记录启动失败；请求线程报错也不能依赖不存在的 stderr。[Python sys 文档](https://docs.python.org/3/library/sys.html#sys.__stdout__)

启动器实施要求：

1. 用实际可用解释器的绝对路径；不固定假设所有机器都有同一 Python313 安装目录。脚本、工作目录和参数分别引用，能从任意当前目录启动。
2. 获取 Windows Known Folder Desktop，兼容 OneDrive/桌面重定向；避免把 `C:\Users\d\Desktop` 当所有部署的事实。bat 保留 CRLF，正文优先 ASCII 或选定可验证编码，不照搬 cp936 处理任意 Unicode 路径。
3. 以短超时访问 `/api/health`，核对 `app_id=open-melayu`、协议/schema、build_id 和 ready；TCP LISTENING 或 HTTP 200 不证明是本项目。错误服务占用 8766 时明确提示，不杀进程、不改 8765、不偷偷改端口。
4. 端口 bind 为最终仲裁。快速双击可能同时启动；优先 Windows 独占监听语义（若支持，明确 SO_EXCLUSIVEADDRUSE 策略，不盲开地址复用），或单实例锁配合 bind；失败的后启动实例退出后重查健康，不能形成两个服务。
5. Hidden 启动 pythonw 后轮询健康，成功才打开浏览器；固定 sleep 1 秒不能判就绪。设有限等待、退出码与可查日志。禁止未经授权增加开机任务或系统服务。
6. pythonw 只意味着无控制台，不能承诺崩溃自动重启、注销后存活或重启后自动运行。预期行为应是“同一用户会话内运行；失效后再次双击可恢复”。测试启动器退出后服务仍响应。

本轮只规定验收，没有启动/终止任一 8765/8766 服务，也没有创建桌面文件。

### 6.3 HTTP 与线程边界

只绑定 `127.0.0.1:8766`；明确拒绝意外 Host，避免把 loopback 绑定等同于所有访问面都安全。前端同源不需要继承旧 `Access-Control-Allow-Origin: *`。新站只开放必要 GET/HEAD/健康接口，不将数据生产或任意文件读取暴露为 HTTP 写接口。

显式设置 `.html`、`.css`、`.js/.mjs`、`.json`、`.svg`、`.woff/.woff2` 的 MIME；文本数据按 UTF-8，Content-Length 计算编码后字节；可加 nosniff。路径不存在返回 404，不泄漏本机绝对路径/堆栈。避免依赖 Windows 注册表猜测模块 MIME。支持 HEAD，错误连接/BrokenPipe 记录后正常结束请求。

ThreadingHTTPServer 足以支持单机本地只读使用，但不是限流或公网生产服务。对连接超时、后台预取并发、整文件内存读入设置边界；不要让大量并发请求每次复制十余 MB 分片且永久挂线程。若保留健康内存状态，使用不可变快照/锁更新；manifest 在磁盘更新后必须重新验证并安全载入，不能永远报告进程启动时的旧 build。旧 SQLite 代码若不再需要应移除，不能保留隐式建空库的相对路径副作用。

## 7. 检索、Malay 与内容真实性：C07/C09–C11

### 7.1 检索契约

索引明确字段类型与缺失值约定。`p` 不能把 IPA 和音节混成无标签字符串；可使用独立 phonetic/syllables 字段。保留 Rumi/Jawi 原始显示，检索用单独规范化键（Rumi NFC + 大小写规范化；Jawi 另建允许的宽松键）。不可为了“匹配更宽”就覆写官方原文或随意合并 Jawi 不同字母。

“中文释义全文”若定义为所有 `senses[].zh_definition`，索引必须包含每个义项的完整中文，而不只是核心摘要；若还要搜语用、词源、例句翻译，则需额外字段与容量预算。**仅有摘要 s 无法兑现中文全文检索。** 推荐本轮把全文明确为全部中文义项；列表摘要独立生成，不截断检索文本。未精编词只有马来语原义时不会自然拥有可搜中文，不能暗示覆盖全 15k 中文。

推荐排序：精确词头 > 精确别名 > 前缀 > 可信词族/其他包含 > 有界模糊，具体跨类次序由修订方案固定。`tak` 已是独立精编词，应首先命中 tak，同时提供 tidak 关联，不能被别名重定向吞掉。别名一对多，`x` 等含上下文歧义的缩写不能强制只有一个“正确词”。未经审核的 Malaya 候选映射不直接升格为标准拼写事实。

根词检索按可信关系倒排，包括根本身；`mereka` 的代词义不能自动套用动词 me- + reka 的解析。词族芯片可能指向池外的词：有 ID 才打开详情；未收录时明确说明，不捏造 URL 后返回首页。Jawi 搜索必须确实查询 j/其规范化键，不能只把英文 key 检索函数改个标签。

Worker 请求使用递增 requestId + build_id，主线程只应用最新响应；详情另有 selectionId，缓存加载成功不能覆盖用户已切换的新词。初始化前只保留最新查询，错误后可重新初始化；UI 处理 Worker error/messageerror。中文 IME 在 compositionend 后发正式检索，快捷键在输入框/编辑区/组合输入时不抢事件。分页、排序、哈希深链、前后导航和词族跳转共享稳定 ID。

### 7.2 Jawi 排版

此处应称 Jawi（爪夷文），它与爪哇文字 Javanese 是不同文字体系；文档和实现不得按名称误选字体或 Unicode 范围。

Jawi 片段使用 `lang="ms-Arab" dir="rtl"`，外层维持中文/Rumi 正常方向；混排用 bdi 或等价隔离。不要将整个词头行设 RTL，不把字符串倒序来模拟 RTL，避免用 letter-spacing 和逐字符 span 破坏连字。输入框使用 dir=auto，并验证光标、选择复制和标点位置。[MDN dir](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/dir)

Traditional Arabic 有阿拉伯排版/波斯字符扩展能力，但不能由此推断目标 Windows 安装都具备完整 Jawi 字形。至少验证 `چ` U+0686、`ڠ` U+06A0、`ڤ` U+06A4、`ڬ` U+06AC、`ڽ` U+06BD 及本库实际使用的 `ک` 等字母在孤立/词中/词末的形态；比较按原始码点而非肉眼近似。Unicode 图表用于识别字符，不能代替字体字形验收。[Microsoft Traditional Arabic](https://learn.microsoft.com/en-us/typography/font-list/traditional-arabic)、[Unicode Arabic 字符表](https://www.unicode.org/charts/PDF/U0600.pdf)

优先选定经码点覆盖和视觉检查的字体；如随应用提供，使用可再分发许可的本地字体文件并纳入 SW 壳缓存、字号/行高测试，保留许可。不能复制 Windows 商业字体文件当默认可分发素材。字体缺失时显示原文并合理回退；不以错字形替代官方拼写。

### 7.3 Web Speech API

Windows 官方声音列表包括 Malay Rizwan、Indonesian Andika；这证明系统存在相应支持路径，不证明每台 Win10/11 已安装，也不证明 Chrome/Edge/Firefox 会暴露同一集合。[Microsoft 支持语言与声音](https://support.microsoft.com/en-us/accessibility/windows/narrator/appendix-a-supported-languages-and-voices)

实现时先检测 `speechSynthesis` 和 `SpeechSynthesisUtterance`；getVoices 初始可能为空，监听 voiceschanged 并有限重试，之后每次点击可重新探测；不要永久记住首次空列表。按语言标签规范化匹配 ms-MY，然后 id-ID；若选 id-ID，将 utterance.lang 与 voice.lang 一致并提示“印尼语近似朗读”，不能冒充标准马来语示范。均无则友好提示，并保持按钮可恢复。[MDN getVoices](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices)

朗读在用户点击内触发，使用 Rumi 单词/例句；Jawi 字形不直接交给发音器当相同文本。切词/再次点按 cancel 前一段，用 generation 标识防旧 end/error 回调改写新按钮。处理异常、language/voice unavailable、not-allowed、synthesis-failed、audio-busy、network、取消及有限 watchdog，所有路径恢复可用按钮。[MDN 语音错误](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisErrorEvent/error)

Web Speech 免费接口不意味着所有 voice 都本地、离线可用。离线优先 localService；没有合适本地 voice 则提示不可离线朗读。若为严格不联网模式，排除 localService=false；在线使用浏览器提供的远程 voice 也须有明确边界，不新增付费 API。[MDN localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)

### 7.4 七维视觉与来源

平铺展示既定七维，空字段用简明“资料待补”，不为 source_only 伪造构词/词源/语用或空认证卡。金色徽章应表示“本工程七维精编”，仅在 schema 和质量门禁通过时显示；不能让用户误解为 DBP 对七维认知内容的官方认证。formal 例句在现有两批是新编内容，必须标为“正式语体例句”，不能改称“报章/学术原句”；真实引用必须可追溯。聊天气泡标注示例，不暗示来自私人真实聊天。[本地 Batch 2 来源说明](BATCH_2_NOTES.md)

所有词典字段均按外部输入处理，以 textContent 或完整转义后模板渲染，不直接将原始释义/词头插入 innerHTML。限制 URL 协议与来源链接，防 javascript:、HTML 属性及 `</script>` 注入。这个要求直接针对本地预览生成器的原始模板拼接风险；未声称已有输入含恶意内容。

无 Tailwind 运行时也能用 CSS `:active { transform: scale(.98) }` 实现药丸反馈；`active:scale-[0.98]` 只是工具类表达，不构成必须引入在线 CDN 的理由。保留指定曲线、transform/opacity 动效；该 cubic-bezier 是缓动曲线，不能将它描述为真实物理弹簧求解。支持 prefers-reduced-motion、可见焦点、200% 缩放、红黄警示文字与图标，不只靠颜色。七维默认展开不等于所有内容必须挤进一屏。

### 性能测量口径与建议接受线

接受线是本次建议的可测目标，尚未经双模型修订确认或实测通过；任何声称原文 <5ms / <2s 已达成的报告都必须附原始测量。

| 场景 | 基准方式 | 建议门槛/裁决 |
| --- | --- | --- |
| 导出 <2s | 15k 真输入，记录每阶段耗时、文件数、总字节、冷/热文件缓存与至少 5 次测量 | 先测后定；此值不是当前阻止功能上线的硬条件，但不得冒称已实测 |
| Worker 查询 | 索引 ready 后，普通前缀/中文/词族/别名/模糊分别准备至少 100 次有效样本；计 p50/p95，包含宽前缀和无结果长词 | 普通查询 p95 目标 ≤5ms；有界模糊 p95 目标 ≤20ms；未达时优化或修订指标，不用平均值冒充最坏值 |
| 输入到列表可见 | 从输入事件经排队、postMessage、排序、主线程渲染至帧呈现；冷启动另计 | p95 目标 ≤100ms，不能只显示 Worker elapsed 代替端到端 |
| 详情切换 | 冷 localhost 分片、IDB 热读、内存命中分别测，重点 m/p/b/s；记录下载/解析/克隆/渲染 | 本机冷片 p95 目标 ≤500ms，热读到可见 p95 ≤100ms；无 >50ms 主线程长任务 |
| 内存 | DevTools 分离主页面与 Worker；冷启动峰值、索引稳定后、三个大分片、反复切片/重建 Worker、双标签页 | 单 Worker 索引预算目标 ≤50 MiB；全页新增稳态 JS 堆目标 ≤150 MiB，启动峰值单列，反复操作无持续增长；超标应分析并修订预算 |

每次记录 CPU/RAM、OS、浏览器及版本、数据 build_id、样本集、是否 GC/节流、是否服务器/磁盘热缓存。20 词测试可验证交互和 schema，不能证明 15k 或未来全量精编状态的性能；暂缺全量精编时可用明确标识的隔离合成负载测容量，但不能声称已验证全量词条内容。
